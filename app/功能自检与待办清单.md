## 一、你提的两个问题（已核实，都成立）

### 1.1 上传题库的入口 —— 存在，但藏得太深

**现状**：入口在 `题库 → 我的题库（/practice/sets）` 页面里的「上传资料」按钮。
也就是说要：点「题库」Tab → 滚到底部「我的题库」区块 → 点「自建题库 / 上传导入」→ 才看到上传按钮。
**四级深度，难怪找不到。**

而且当前上传是**演示态**：点完只弹一个 alert，没有真实的「解析 → 预览确认 → 入库」流程
（PRD M7-F3 明确要求：绝不静默入库，必须逐题展示置信度让用户确认）。

**建议**：把入口提到「题库」页**首屏顶部**，做成一张醒目的卡片：

```
┌────────────────────────────────┐
│ 📤 把你的资料变成练习题          │
│ PDF / Word / 图片 / 拍照 / 粘贴  │
│              [ 立即上传 › ]      │
└────────────────────────────────┘
```

### 1.2 科目切换 —— 确实缺失，这是硬伤 ⚠️

**核查结果**：6 个跳转答题页的入口里，**有 5 个根本没传科目**：

| 入口 | 是否传科目 |
|---|---|
| `PracticePage.vue:17`（6 种练习模式） | ❌ 没传 |
| `WrongBookPage.vue:61`（错题重做） | ❌ 没传 |
| `QuestionSetPage.vue:64`（自建题库练习） | ❌ 没传 |
| `TodayPage.vue:45`（任务包） | ❌ 没传 |
| `KnowledgeDetailPage.vue:28`（章节练习） | ❌ 没传 |
| `OnboardingPage.vue:47`（摸底测评） | ✅ 传了 |

而 `QuizPage.vue:16` 是 `(route.query.subject as SubjectId) || 'econ_base'`——
**没传就默默默认成「经济基础」**，页面上也**没有任何地方显示当前是哪个科目**。

结果就是：你在题库点「章节练习」，刷的永远是经济基础；想刷人力，**没有任何入口**。
上传了多科题目后更是无从切换。这与 PRD 双科目的产品定义直接冲突。

**推荐方案：全局科目状态（Store）**

```
stores/subject.ts（Pinia）
  ├─ currentSubject: 'econ_base' | 'hr'
  ├─ setSubject(id) —— 持久化到 localStorage
  └─ 初始化取 onboarding 选择的第一个科目
```

配套改动（工作量小，约 4 个文件）：

1. **新建** `src/stores/subject.ts`
2. `QuizPage.vue`：顶部加「经济基础 ⇄ 人力资源」切换条 + 当前科目标签；
   `subjectId` 改为从 store 读取（路由参数作为覆盖）；切换时重新组卷
3. `PracticePage.vue` / `TodayPage.vue`：顶部加科目指示 chip，点击可切换
4. 其余入口不再需要传 `subject`（统一读 store）

**为什么不继续用路由参数**：科目是贯穿全局的状态，不是单次请求的筛选条件。
放 store 后，任务包生成、复习队列、掌握度统计、过线预测都能自动跟随当前科目，不会出现「首页显示人力、点进去刷经济基础」的割裂。

## 七、导入归类 + 图文识别 ✅（2026-09-08）

### 题目归类（本地关键词匹配，零成本、可离线）

| 维度 | 判定方式 |
|---|---|
| **科目** | 用户预设为主；`classifyQuestion` 跨两科匹配，命中另一科时预览页提示「建议科目」 |
| **章节/知识点** | 题干/选项含知识点名 → 高置信(0.9)；含章节名 → 中置信(0.6)；无命中 → 标记「未归类」，入库后可手动指定 |
| **题型** | 选项数+答案数自动推断（单选/多选） |
| **难度** | 默认 3，用户可改 |

实现：`importService.classifyQuestion()`，纯函数、确定性、无需联网。
选择关键词匹配而非 AI 的理由：考试题干几乎必然出现考点术语，本地命中率高、零成本，
符合本地优先架构；AI 作为后续可选增强。

### 文件解析（OCR / PDF / Word / Excel）

| 文件 | 解析器 | 依赖 |
|---|---|---|
| 图片 | tesseract.js OCR（chi_sim+eng） | `tesseract.js` |
| PDF | pdf.js 文字提取；扫描版自动逐页渲染 OCR | `pdfjs-dist` |
| Word | mammoth 提取 .docx 文本 | `mammoth` |
| Excel | SheetJS 逐行读 .xlsx/.csv | `xlsx@0.18.5` |

统一入口 `infrastructure/fileParse/index.ts` 的 `extractFileText()`，输出纯文本，
再走 `parseText` 切题 + `classifyQuestion` 归类，职责分离。

### ⚠️ 需要你自己安装的依赖（不执行 npm install）

```bash
cd app
npm install tesseract.js pdfjs-dist mammoth xlsx@0.18.5
```

注意事项：
1. **tesseract.js 中文语言包**：首次识别时自动从 CDN 下载 chi_sim（约 10-20MB），
   需联网；生产/PWA 离线需配置本地语言包路径。
2. **pdfjs-dist worker**：已在 `pdf.ts` 用 `?url` 导入，随构建打包，无需额外配置。
3. **xlsx 版本**：SheetJS 官方已停止向 npm 发布新版，社区版停在 0.18.5（有安全告警但功能可用）；
   生产环境可换 exceljs 或官方 CDN。
4. `vite.config.ts` 已把 tesseract.js / pdfjs-dist 加入 `optimizeDeps.exclude`。

## 八、识别规则系统 ✅（OCR 精确度，2026-09-09）

### 问题

OCR 不精确：多题被识别成一题、解析被当成选项、页码页眉等噪音未排除。
根因是硬编码正则无法覆盖千差万别的文档格式。

### 方案：把识别规则外置为可配置项

用户提的方向是对的——**规则外置 + 预设模板 + 实时预览**。

| 能力 | 说明 |
|---|---|
| **预设模板** | 标准（`1.`）、括号（`(1)`）、中文（`第1题`）、OCR 标点容错（4 种） |
| **自定义规则** | 题号 / 选项 / 答案三条正则 + 跳过关键词 + 去噪开关，可保存复用 |
| **去噪** | 页码（纯数字、`- 3 -`、`第 3 页`）、页眉页脚（重复 ≥3 次短行）、连续重复标点 |
| **两道防污染** | ① 答案出现后不再收集选项 ② 选项字母必须递增（阻断解析里的"A项…"） |
| **试解析** | 用当前规则解析样本文本 → 显示「识别到 N 题」+ 前 3 题预览，验证通过再导入 |

### 关键文件

- `domain/services/parseRule.ts`：规则模型 + 4 预设 + 安全编译 + 去噪 + 持久化
- `domain/services/importService.ts`：`parseText(raw, subjectId, rule?)`，不传规则用默认（向后兼容）
- `pages/practice/ImportPage.vue`：规则配置面板 + 试解析
- `scripts/test-parse.mjs`：验证脚本，`node scripts/test-parse.mjs`（7 项断言）

### 验证结果

```
✅ 切题数量: 3        ✅ 第1题答案: ["A"]
✅ 第1题选项数: 4     ✅ 第2题答案: ["C"]   ✅ 第3题答案: ["B"]
✅ 页码/页眉已去除    ✅ 解析未混入选项
```

## 十六、AI 模考复盘报告六维度 ✅（P2，2026-09-18）

> 依据 PRD M5-F5。此前模考只展示「分数 + 遗憾分」，缺四个维度。

### 六维度落地情况

| 维度 | 实现 |
|---|---|
| ① 总分与过线判断 | 得分 / 合格线 / 差值 / **过线概率**（新增） |
| ② 题型得分分析 | 单选·多选·案例得分率 + 与目标（85%/58%）的差距（新增） |
| ③ 模块得分分析 | 按「章」聚合得分率，**拖后腿的排前面**（新增） |
| ④ 时间分配分析 | 平均单题用时 vs 建议用时 + 耗时最长 5 题（新增） |
| ⑤ 遗憾分分析 | 复用 `analyzeRegret`（粗心 / 少选 / 未作答 / 超时） |
| ⑥ 下一步建议 | 规则生成（**无需 API Key**）：薄弱模块 + 多选策略 + 审题 + 速度（新增） |

### 关键实现

**1. 模块聚合**：题目只带 `knowledgeNodeIds`，需**向上回溯到章（level 2）**：
```
知识点(k1) → 找 parentId → 章(ch2) → 聚合
```
找不到章的归入「未归类」，不丢失统计。

**2. 过线概率模型**：用 logistic 形式逼近正态 CDF，标准差取 8 分：
```
p = 1 / (1 + e^(-1.7 × (score − 84) / 8))
```
不给出过于自信的数字（模考与真题难度有波动）。

**3. 单题用时采集**（复盘④的前提）：
- 新增 `timeSpent: Record<questionId, ms>`，**同一题多次进入会累加**

  结算「离开的题」——必须在改 `qIdx` **之前**调用，否则时间会记到下一题头上
- 提交时也 `flushTime()`，否则最后一题用时丢失

**4. 建议用规则而非 AI**：无 API Key 也能给出可执行动作（薄弱模块一键去练），

## 十七、元认知校准图 ✅（P2，2026-09-18）

> 依据 PRD M8-F1 第 3 点「元认知校准图（特色）」+ §13.2「校准偏差目标 < 15%」。
> 回答一个问题：**你「以为自己会不会」的判断，准不准？**

### 为什么这个图有价值

「很确定」却答错的题，是**最危险的失分**——因为你不会去复习它（压根没意识到不会）。
反过来，「完全没思路」却答对，说明知识点是模糊的，靠的是运气。
这张图把这两种情况变成看得见的账。

### 数据侧

- `AnswerLogRepository.confidenceStats()`（新增，mock + sqlite 双实现）
  - sqlite 用 SQL 聚合：`GROUP BY confidence` + `SUM(CASE WHEN is_correct ...)`
  - **只统计有自评的记录**（模考的 `confidence` 为 null，必须排除）
- `analyzeCalibration()`（`metacognitionService.ts`）

**隐含把握率模型**（把分类变量变成可比较的数值）：

| 确信度 | 隐含把握率 | 依据 |
|---|---|---|
| 很确定 | 90% | 用户自评时心里的预期 |
| 有点懵 | 55% | 一半一半 |
| 没思路 | 25% | 四选一随机 |

**校准偏差** = 按题量加权平均 `|实际正确率 − 隐含把握率|`，目标 < 15%。

**小样本保护**：每档至少 5 题才纳入统计，避免"3 题全错 → 偏差 90%"的失真结论。

  1. 过度自信（最危险，优先说）

## 十八、自适应难度引擎 ✅（P2，2026-09-18）

> 依据 PRD M3-F4。目标：把练习正确率锚定在 **85%**（最近发展区最优）。

### 调节规则（严格按 PRD）

| 条件 | 响应 |
|---|---|
| 正确率 > 92%，连续 2 个窗口 | 难度 +1 |
| 正确率 < 70%，连续 2 个窗口 | 难度 −1，并标记插入基础题 |
| 落在 70%~92% | 保持，且**清零连续计数** |
| **连续答错 3 题** | 立即降难度 + 插入简单题（情绪保护） |
| 难度已到 1 / 5 | 不再越界 |

### ⚠️ 实现中修正的两个语义问题（测试发现的）

**1. 「连续 2 个窗口」必须是独立批次，不能用滑动窗口**

初版按"最近 20 题"滑动评估，导致每答一题就评估一次，连续计数在几题内就累加满
（第 2 个"窗口"其实只是移动了一题）。**修正：评估后无条件清空窗口**，
形成真正的「批次」语义，才符合 PRD 的"连续 2 次"。

**2. 情绪保护在最低难度时也要生效**

初版写成 `if (wrongStreak >= 3 && difficulty > MIN_D)`——难度已在 1 时整段跳过，
连错 3 题什么反馈都没有。**情绪保护的目的不是改难度，是接住挫败感**。
修正：拆开判断，即使不能降难度也返回 `insertEasy: true`。

### 接入方式

- **组卷**（mock + sqlite 的 `buildPaper`）：
  - `special` 从「精确匹配」改为 **±1 区间**（精确匹配常抽不满）
  - `chapter` 也支持难度（原先完全不传）
- **QuizPage**：
  - 只对 `chapter` / `special` 生效（复习/错题/真题/高频各有选题规则，不该被干预）
  - 用户在专项里手动选了难度时，**以用户选择为准**
  - 答题后 `recordResult()`，难度变化时在解析区展示一次提示
  - 加了 `if (submitted) return` 守卫，防止重复提交导致重复计数

### 验证

新增 `scripts/test-adaptive.mjs`（**21 项断言**）：升降档触发 / 目标区清零 /
情绪保护 / 难度边界 / 窗口长度。**7 套测试全部通过**。

> 测试自身踩的坑：造的"目标区"序列开头有 3 个连续错误，**直接触发了情绪保护**
> 导致难度被降。这反而验证了保护机制的灵敏度 —— 也提醒测试数据要考虑副作用。

### 遗留

## 十九、免学跳关 ✅（P2，2026-09-18）

> 依据 PRD §6.6：「章节测正确率 ≥ 90% 且确信度自评高 → 允许跳学」。
> 服务层的 `decideChapterAction` 早已写好，本轮把它接进答题流程。

### 实现

1. **记录本轮确信度**：`confHistory`，在 `submit()` 时 push
2. **主导确信度**：本章多题的确信度取**众数**作为"整章自评"
3. **推进建议**（章节练习完成时）：
   | 条件 | 建议 | 按钮 |
   |---|---|---|
   | 正确率 ≥ 90% 且自评有把握 | 这一章可以跳过 | 跳过本章，去下一章 |
   | 正确率 < 60% | 先别急着往下走 | 回看本章精讲 |
   | 其他 | 继续推进 | — |
4. **跳转**：`goNextChapter()` 按 `order` 找同级下一章（level 2），已是最后一章则回今日任务

### ⚠️ 并列时的保守策略（测试抓出的实现与注释不符）

初版代码注释写的是"并列时取更保守档位"，但实现是 `if (c.sure === max) return 'sure'`——
**优先级写反了**，`['sure','unsure']` 会返回 `sure`。

修正为：「很确定」必须**严格最多**才算主导：
```ts
if (c.sure === max && c.sure > c.unsure && c.sure > c.noidea) return 'sure'
```
理由（NR 原则）：跳学是"少练"的决策，宁可多练一章，也不要因判断宽松而漏掉薄弱点。

### 遗留

- 跳学目前是"人肉确认"（点按钮），未做"系统自动标记章节完成"
- 未记录"已跳过的章节"以便后续回访
