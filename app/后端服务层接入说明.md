# 后端（本地数据服务层）交付说明

> 本阶段「后端」= **本地数据服务层 + 业务逻辑层**。
> 项目是纯本地架构（无远程数据库、无服务端），所以后端不是 HTTP 服务，而是跑在浏览器里的
> **Repository（数据访问）+ Service（业务逻辑）** 两层。

### 架构关系（重要）

```
页面（pages/）
   │  只调用服务，不写业务逻辑
   ▼
Service 层（domain/services/） ← 本次新增
   │  只依赖接口，不关心实现
   ▼
Repository 接口（domain/repositories.ts）
   │
   ▼
实现：sqlite（真实 SQL） / mock（内存降级）
```

`PlanService` 负责**生成**任务包，`PlanRepository` 只负责**存取**。
之前生成逻辑写在 mock 数据源里，现在上移到 Service 层，两个数据源都能复用。

## 二、接入点（4 处，请在你编辑器中修改）

> 不改的话服务层不会生效。每处改动都很小。

### 1️⃣ `src/pages/exam/ExamRoomPage.vue` —— 计分逻辑下沉（最重要）

现在计分是页面里手写的 `grade()`。改为调用服务：

```ts
// 顶部 import 区新增
import { gradePaper, sectionsOf, PASS_LINE } from '@/services'

// 删除页面内的 function grade() { ... }（约 25 行）

// submitExam() 中：
//   const score = grade()
//   const passed = score >= 84
// 改为：
const result = gradePaper(paper.value, SECTIONS, answers.value)
const score = result.score
const passed = result.passed
```

同时 `SECTIONS` 可直接用 `sectionsOf(subjectId)` 替换页面内的硬编码定义。

### 2️⃣ `src/pages/exam/ExamRoomPage.vue` —— 复盘页加「遗憾分」

在 `submitExam()` 保存记录前，把作答流水写入并计算遗憾分：

```ts
import { analyzeRegret } from '@/services'

const logs = await getDataSource().answerLogs.listBySession(sessionId)
const regret = analyzeRegret(paper.value, answers.value, logs)
// 存到 ExamRecord 或在结果页展示 regret.total / regret.items
```

### 3️⃣ `src/pages/study/TodayPage.vue` —— 首页走计划引擎

```ts
// 原来
import { getDataSource } from '@/infrastructure'
overview.value = await getDataSource().plan.getTodayOverview()

// 改为
import { getServices } from '@/services'
overview.value = await getServices().plan.getTodayOverview(60)
```

### 4️⃣ `src/pages/quiz/QuizPage.vue` —— 掌握度改为批量重算

现在每答一题都 `mastery.upsert()`（会卡顿，PRD 明确要求避免）。改为累计触发：

```ts
import { getServices } from '@/services'

// rate() 中，把原来的「掌握度增量更新」整段替换为：
answeredInSession++
if (answeredInSession % 20 === 0) {
  // 批量重算当前科目（后台执行，不阻塞）
  getServices().mastery.recomputeSubject(subjectId)
}
```

## 四、数据源说明（无需改动，但要知道）

| 数据源 | 触发条件 | 表现 |
|---|---|---|
| **SQLite（默认）** | 浏览器支持 OPFS（Chrome 108+ / Safari 16.4+ / Firefox 111+） | 真实 SQL，数据持久化到 OPFS 的 `/jingshi.db`，刷新不丢 |
| **Mock（自动降级）** | SQLite 初始化失败（如 Safari 无痕模式不支持 OPFS） | 内存 + localStorage，控制台会打印降级原因 |

切换：`.env` 中设 `VITE_DATA_SOURCE=mock` 可强制使用内存数据源。
「我的」页会显示当前数据源与降级原因。

### ⚠️ VFS 选择（2026-09-11 修正）

Worker 里按以下优先级打开数据库（`src/worker/sqlite.worker.ts`）：

1. **`opfs-sahpool`**（默认）—— `installOpfsSAHPoolVfs()` → `new pool.OpfsSAHPoolDb('/jingshi.db')`
   持久化，且**不需要 COOP/COEP 响应头**，部署友好。
2. **`opfs`** —— `new sqlite3.oo1.OpfsDb('/jingshi.db')`，需要 COOP/COEP（依赖 SharedArrayBuffer）。
   本项目未配置这两个头，所以它恒为 `undefined`。
3. 都不可用 → 抛错，上层降级为 Mock。

> 曾经的坑：代码误用 `sqlite3.oo1.OpfsDb`（属于 `opfs` VFS），在未配 COOP/COEP 的环境下
> 它是 `undefined`，`new` 时报 `sqlite3.oo1.OpfsDb is not a constructor`。
> 注意 `oo1` 命名空间里**没有** `OpfsSAHPoolDb`，sahpool 版必须通过 `installOpfsSAHPoolVfs()` 拿。

## 七、已修复问题 + 交付前自检（第四轮）

### 报错

```
Uncaught (in promise) TypeError:
getDataSource(...).plan.getTodayOverview is not a function  at load (TodayPage.vue:21:47)
```

**根因**：第二轮把 `getTodayOverview()` 从 `PlanRepository` 移入 `PlanService`（它是业务规则，
不该留在仓储层），但 `TodayPage.vue` 仍按老方式 `getDataSource().plan.getTodayOverview()` 调用，
仓储层已无此方法。

**修复**：`TodayPage.vue` 改为 `getServices().plan.getTodayOverview()`，
并移除不再需要的 `getDataSource` import。

> 教训：接口方法迁移时，调用方不会自动跟着改。这类问题 TypeScript 能直接抓出来
> （`Property 'getTodayOverview' does not exist on type 'PlanRepository'`），
> 所以**跑一次类型检查是迁移后的必要动作**。

### 自检结果

| 检查项 | 方法 | 结果 |
|---|---|---|
| Repository 方法调用 | 全量 Grep 所有 `ds()/getDataSource()/.xxx.yyy()` 调用点，逐个对照接口定义 | ✅ 25 处调用全部存在于接口 |
| Service 方法调用 | 全量 Grep `getServices()/svc.xxx.yyy()` | ✅ 14 处调用全部存在 |
| 双实现接口完整性 | Grep mock 与 sqlite 两个实现的 `dailyCounts / saveTaskPack / createSnapshot / getSnapshot / deleteSnapshot / listSnapshots / getTaskPack / markPackCompleted` | ✅ 两边都已实现，无缺方法 |

### ⚠️ 已知工具链问题（需你决策）

`vue-tsc@3.3.11` 与 `typescript@7.0.2` **不兼容**：

```
Error [ERR_PACKAGE_PATH_NOT_EXPORTED]:
Package subpath './lib/tsc' is not defined by "exports" in typescript/package.json
```

TypeScript 7 改为原生实现后包导出结构变了，vue-tsc 找不到 `lib/tsc`。
**影响**：`npx vue-tsc --noEmit` 无法运行，`.vue` 文件拿不到类型检查（这是本次 bug 没能被自动发现的原因）。

两个可选方案（都需你执行，因为涉及安装）：

```bash
# 方案 A：降级到稳定组合（推荐，可恢复类型检查）
npm install -D typescript@5.7 vue-tsc@2.2
npx vue-tsc --noEmit

# 方案 B：保持现状，仅靠 vite build 兜底
#   注意：vite build 只做转译不做类型检查，类型错误不会导致构建失败
npm run build
```

在类型检查恢复前，建议每次改动接口后用 Grep 核对调用点（本文件第四节记录了接口变更）。

## 八、架构约定（后续必须遵守）

**页面只做渲染与交互，规则一律进 Service。**

- 计分规则 → `examService`（绝不在页面里写第二份）
- 任务包生成 → `planService`（Repository 只存取）
- 掌握度算法 → `masteryService`
- 过线概率 → `predictionService`
- 快照时机与保留策略 → `backupService`
- AI Prompt 与校验 → `aiService`

页面通过 `getServices()` 拿到服务，任何新增业务规则都放进 `src/domain/services/`。
